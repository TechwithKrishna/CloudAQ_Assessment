# Task 2: AI-Powered Natural Language Browser Testing

## Project Overview

This project implements an **AI-powered browser automation and testing system** using Python, Google Gemini, and Playwright.

The system accepts a website URL and a plain-English test case. Google Gemini understands the test instruction, analyzes the webpage elements, and generates browser actions in JSON format. Playwright executes those actions automatically.

The objective is to reduce the need to write separate browser automation scripts for every test scenario.

## Objectives

- Accept website URLs dynamically.
- Understand test instructions written in natural language.
- Inspect webpage elements automatically.
- Generate browser actions using Google Gemini.
- Execute browser actions using Playwright.
- Verify expected results.
- Capture screenshots when test execution fails.

## Technology Stack

- Python
- Google Gemini API
- Gemini 2.5 Flash
- Playwright
- Chromium
- python-dotenv
- JSON

## Key Features

### 1. Natural Language Test Instructions

Users can describe a test scenario in plain English instead of writing individual automation commands.

Example:

"Open the login page, enter the email address, click Login, and verify that the Dashboard heading is visible."

### 2. Automatic Webpage Inspection

The system inspects visible webpage elements, including:

- Input fields
- Buttons
- Links
- Dropdowns
- Textareas
- Headings

It collects useful information such as element tags, text, placeholders, labels, and accessibility attributes.

### 3. AI-Based Action Generation

Gemini analyzes:

- The user's test case
- Current website URL
- Available webpage elements
- Previously executed actions

It returns the next browser action as a JSON object.

### 4. Browser Automation with Playwright

Playwright executes the actions generated by Gemini.

Supported actions include:

| Action | Description |
|---|---|
| fill | Enter text into an input field |
| click | Click a button or element |
| select_option | Select a dropdown option |
| assert_text | Verify visible text |
| assert_visible | Verify element visibility |
| assert_url | Verify the current URL |
| wait | Wait for a specified duration |
| need_input | Request additional information |
| done | Finish the test |

### 5. Multiple Locator Strategies

The application supports:

- Role-based locators
- Label-based locators
- Placeholder-based locators
- Text-based locators

It also checks for ambiguous matches before performing fill, click, and dropdown actions.

### 6. Error Handling and Retry Mechanism

The Gemini API request is retried up to three times when an error occurs.

The browser automation also reports failures when an element is missing, ambiguous, or cannot be interacted with.

### 7. Screenshot Capture

When test execution fails, the application attempts to save a screenshot as:

`failure.png`

### 8. Test Result Reporting

The application reports:

- TEST RESULT: PASS
- TEST RESULT: FAIL

A successful completion requires at least one successful assertion before the AI returns the done action.

## Installation and Setup

### Step 1: Install Python

Install Python and verify:

```powershell
python --version
```

### Step 2: Create a Virtual Environment

```powershell
py -m venv .venv
```

Activate it:

```powershell
.\.venv\Scripts\Activate.ps1
```

### Step 3: Install Dependencies

```powershell
pip install google-genai playwright python-dotenv
```

Or install from the requirements file:

```powershell
pip install -r Requirements.txt
```

### Step 4: Install Chromium

```powershell
python -m playwright install chromium
```

## API Configuration

Create a `.env` file in the Task2 directory:

```env
GEMINI_API_KEY=your_gemini_api_key
```

Replace the placeholder with your actual Gemini API key.

The application loads the API key using `python-dotenv`.

## How to Run

Execute:

```powershell
python main.py
```

The application asks for two inputs:

```text
Enter website URL:
Enter plain-English test case:
```

Enter the target URL and describe the test scenario.

## Execution Workflow

1. User enters a website URL.
2. User provides a natural-language test case.
3. Playwright launches Chromium.
4. The browser navigates to the website.
5. The application inspects visible webpage elements.
6. Gemini analyzes the page and test requirements.
7. Gemini generates the next action in JSON format.
8. Playwright executes the action.
9. The action is added to execution history.
10. The process continues until the test is completed or fails.
11. The final test result is displayed.

## Expected Output

Successful execution:

```text
Opening website: https://example.com

AI Action: {"action": "assert_visible", ...}

TEST RESULT: PASS
```

Failed execution:

```text
TEST RESULT: FAIL
Reason: Input field is missing or ambiguous.
```

A failure screenshot is saved as `failure.png` when possible.

## Safety and Limitations

- API credentials are loaded from environment variables.
- The AI is instructed not to invent credentials or bypass CAPTCHA and security checks.
- The system allows a maximum of 15 browser actions per test.
- Page inspection is limited to 80 matching visible elements.
- Gemini output is parsed as JSON, but production use should also validate it against a strict schema.
- Complex websites, iframes, custom widgets, and dynamic interfaces may require additional locator handling.
- A passing result confirms the assertions executed by the test, not every possible business requirement.
